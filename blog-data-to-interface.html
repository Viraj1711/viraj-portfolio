From a local record to a useful interface

What the attendance and healthcare projects demonstrate about storage, relationships, and usable data.

IN THIS NOTEStart with the smallest useful workflowKeep persistence explicitRelationships create useful questionsBe clear about the application boundary
Editorial draft prepared for this portfolio from the resume, public source, and linked documentation. Review before publishing under Viraj’s name.

Start with the smallest useful workflow

The attendance application provides a simple workflow: enter a name, mark attendance, and view records. A Tkinter interface handles the input while SQLite preserves records in a local file. A timestamp makes each event meaningful when it is read later. The reviewed source focuses on marking a person present, rather than a complete school-management system.

Keep persistence explicit

The app creates an attendance table, inserts records through parameterized SQL, commits changes, and retrieves rows for display. SQLite is a file-based database that does not require a separate database server. Python’s official documentation recommends parameter placeholders for binding values. The repository uses that approach for names, timestamps, and status values.

Relationships create useful questions

Smart Healthcare SQL models patients, doctors, and appointments. The appointment table links to patients and doctors using foreign keys. A reporting query joins the three tables to produce readable appointment information, while an aggregation calculates average waiting time per doctor. This moves the schema beyond a set of disconnected tables.

Be clear about the application boundary

These repositories are focused learning projects. Their source demonstrates storage and query concepts, but it does not establish production security, role management, medical use, or deployed reporting services. A descriptive portfolio is more useful when readers can see both the implemented behavior and the next engineering questions. Further work could explore migrations, pagination, richer validation, and tests around reporting behavior.
