Small Python tools, explicit decisions

How the FastBox simulator makes routing rules, tie breaking, and reporting assumptions inspectable.

A small tool can have a precise contract

FastBox reads warehouse, agent, and package data, assigns each package to its nearest agent, simulates delivery routes, and writes an efficiency report. Its runtime uses only the Python standard library. That narrow scope makes the contract understandable: an input dataset and documented rules should produce a predictable report.

Write the ambiguous rules down

The README explicitly addresses details that are easy to leave implicit. Assignment uses each agent’s original location. Equal distances resolve to the lexicographically smallest agent ID. Packages follow their original input order. An agent does not automatically return to a depot after the last delivery. These decisions make the result explainable and prevent a later refactor from quietly changing behavior.

Keep invalid data out of the core

The loader validates duplicate identifiers and JSON keys, missing fields, coordinates, warehouse references, and packages without agents. Keeping normalization and validation separate from assignment and simulation makes each responsibility easier to inspect. The project structure reflects that separation through parser, models, assignment, simulation, and reporting modules.

Report without hiding edge cases

The report includes agents with zero deliveries. Their efficiency is null, and they are excluded from best-agent selection. Distances are calculated at full precision and rounded only for serialization. Average distance per delivered package is the efficiency measure, so lower is better. The README documents automated tests and a CI workflow; the portfolio does not claim to have executed that external project’s test suite.
